# Qualification resource inventory

This is the resource register for [#118](https://github.com/mopeyjellyfish/flixr/issues/118). It makes no support or qualification claim. A row becomes qualified only when its consumer issue records a clean install or update, exact target details, commands, fixture version, and result for the candidate under test.

## How to use this register

- **Availability** is what can be established now. `External blocker` means no device, account, signing identity, or access has been supplied; it is not a failed test.
- **Owner** is `maintainer (assignment unconfirmed)` for every external resource. No owner, purchase, account, signing identity, publication, or date is inferred here.
- **Evidence path** is where the consumer must attach redacted target evidence. The existing synthetic source is `backend/testdata/media/`, generated by `backend/scripts/generate-media-fixtures.sh` and licensed in `backend/testdata/media/LICENSE.md`.
- The current repeatable local browser installation is `make start`. It starts the supported local web service; it is not an install command for a mobile, TV, receiver, or native client. Those commands do not exist until their consumer implementation supplies them.

## Evidence and acceptance boundary

Use the generated synthetic media in `backend/testdata/media/` for initial repeatability and record its commit in the consumer issue. Add only redacted device details and command output; do not record serial numbers, UDIDs, credentials, tokens, signing identities, or personal account information.

Each packaging consumer must add its real installation/update command once implemented. The required physical acceptance is a clean install or update followed by the issue's named flows; a developer-only launch, simulator, emulator, browser automation, or hardware capability listing does not qualify the target.

Before [#99](https://github.com/mopeyjellyfish/flixr/issues/99) runs, it must consolidate the exact candidate commit/image, fixture revision, target hardware and OS/app versions, commands, outcomes, limitations, and links to the consumer evidence above. Every `External blocker` remains a release blocker until a maintainer records a supported scope change.
