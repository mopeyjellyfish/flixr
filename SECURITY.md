# Security policy

## Reporting a vulnerability

Do not put vulnerability details, exploit steps, setup tokens, passwords, session
cookies, API tokens, TLS keys, media paths, or logs in a public GitHub issue.

Use GitHub's [private vulnerability reporting form](https://github.com/mopeyjellyfish/flixr/security/advisories/new).
It is the repository's confidential reporting route. The GitHub API reported
private vulnerability reporting enabled on 7 September 2026.

For a non-sensitive hardening idea, use the feature-request template and omit all
reproduction details that would make it exploitable.

## Scope and response

Report flaws in FlixR source, published container configuration, authentication,
authorization, media-root confinement, or release artifacts. Third-party package
vulnerabilities should include the package, version, and why the FlixR runtime
path is affected.

Maintainers may acknowledge, investigate, fix, and publish a release, but this
project does not promise a response time, bounty, or coordinated-disclosure date.
